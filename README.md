# Embedded Five9 for Navusoft

Release ZIPs belong in `dist/`, which is excluded from Git along with `.DS_Store` files at any depth. Images remain in `assets/`.

See the [privacy policy](PRIVACY.md) for the extension's data handling disclosures.

This experimental Chrome extension opens a Five9 Agent Desktop iframe from a circular F9 launcher in the bottom-left corner of Navusoft pages at https://bigssanitation.navusoft.net/. The panel is a 500px square that shrinks to fit smaller screens. It starts minimized on every page load, regardless of its previous state. The Five9 iframe still initializes while minimized. When Five9 reports a newly handled call through `callStarted`, the dock opens immediately, independently of contact lookup. Five9 also replays this event after a refresh while handling an existing call, which reopens the dock for that call.

When Five9 starts handling an inbound call, the extension searches Navusoft **Contacts** using the caller's ANI (or contact number if ANI is unavailable). Manual agent calls (`callType: AGENT`) use the same lookup with the dialed `number`, unless Five9 supplies `click2DialData.clickToDialNumber`, identifying a click-to-dial call. Click-to-dial calls and other outbound call types do not trigger a lookup. US numbers with a leading country code are normalized to 10 digits. A single contact match with a site opens that record in Navusoft using its native `Portal.util.Common.displayCustomerScreen` navigation. Multiple matches open Navusoft's native Contacts search and submit the phone number through its search controller, leaving the results grid available for selection. No contact results strip is added to the Five9 dock. Duplicate events within the page are ignored.

Read-only phone numbers become Five9 click-to-dial links, including dynamically loaded grids and record details. Existing telephone links and phone-only links/buttons also route to Five9; editable fields are left unchanged. Unprefixed numbers are interpreted as US numbers, while international numbers should include their country code. Clicking opens the dock and fills Five9's dial dialog through `InteractionApi.click2dial`. Automatic dialing is disabled: the agent must press Five9's Dial button to place the call. Sign in and connect your Five9 station before dialing. Extensions are displayed but are not automatically sent as DTMF.

Phone detection uses the bundled [libphonenumber-js 1.13.15](https://www.npmjs.com/package/libphonenumber-js/v/1.13.15) browser build (MIT license).

Opened accounts are registered with Five9 using `InteractionApi.objectVisited` as **Related To** objects. Account IDs are taken from Navusoft's loaded account data, not site IDs or displayed account numbers. Visits are replayed when Five9 initializes so accounts opened before login are available.

Select the call's account in Five9's **Related To** field before dispositioning. If no account is selected, `beforeDisposition` returns the SDK's `Confirmation` status: "No note will be saved because you have not selected an account. Do you want to proceed with disposition?" Five9 displays its native Yes/No dialog. Yes continues with the original disposition parameters without saving a note or updating Navusoft CAVs; No cancels disposition so the agent can select an account and retry.

The selected Five9 Related To object is the source of truth: the hook reads it with `getSelectedRelatedToObject`, and the final callback supplies it in `callLogData.what`. Note saving extracts a positive, safe integer account ID from the object's `navusoft-account:<id>` value without requiring the account to have been visited since the last page refresh. Empty/placeholder objects, invalid or unrelated IDs, and `NoData` errors from the selection getter use the same confirmation path. No note or CAV write is attempted for those selections. Look for `#### No usable Navusoft account selected; requesting disposition confirmation`. Other SDK errors remain blocking rather than being mistaken for an empty selection.

With a selected account, the hook resolves the chosen disposition ID, then creates an account-level **Service Note** while the call is still active. It uses the selected account even if a different account is currently open. After the note save, it attempts to write `Navusoft.account_id` and `Navusoft.note_id` and verify both values before returning `Proceed`. CAV catalog, configuration, ID validation, write, and readback failures are console-only errors: they log `#### Navusoft CAV synchronization failed; allowing disposition:` and still return `Proceed` without a blocking dialog. Note-save failures and other non-CAV errors retain their existing blocking behavior. The account-level Service Note type must exist in Navusoft; the extension does not create note types or substitute a site-level type.

The initial note contains the call ID, intended disposition, direction, phone, agent, and campaign when available. Five9's pre-disposition payload does not include subject or comments; the final `callFinished` payload updates the same saved note with those details, without creating another note or writing CAVs after finish. If Five9 subsequently refuses disposition during its own internal checks, the saved note records an attempted disposition until completion; retrying the CAV update does not create another note.

The hook retrieves the full domain CAV catalog through `InteractionApi.executeRestApi` using `GET /appsvcs/rs/svc/orgs/{domainId}/call_variables` with `payload: null`. It caches all definitions in memory per domain, sharing in-flight requests across calls and clearing the cache on `sessionInitialized`. Failed or malformed requests are not cached. The domain comes from the call's `domainId`, falling back to `getMetadata().tenantId`. No CAV values or credentials are cached.

After saving the note, the hook resolves **Navusoft.account_id** and **Navusoft.note_id** from that domain catalog. Variables do not need to be populated on the interaction to be found. Lookup accepts separate `group: "Navusoft"` / `name: "account_id"` fields or fully qualified names such as `Navusoft.account_id`, trimming surrounding whitespace. Conflicting groups and duplicate matches are rejected without blocking disposition. The hook writes those IDs using `setCav`; interaction `getCav` is used only to verify the resulting values. If lookup fails, `#### Five9 CAV definitions (values omitted):` reports definition metadata without values. Catalog retrieval or lookup failures do not discard the saved note or prevent disposition.

A valid note model ID is used when available; otherwise the ID is parsed from Navusoft's bare numeric save response and assigned to the saved model for subsequent updates. Invalid IDs are never written to CAVs. These variables must be configured in the Five9 domain; they may initially be absent from the interaction's populated CAV list. The account ID is the internal Navusoft account ID, not its displayed account number. No other CAVs are changed. An optional `Navusoft.account_name` would make reports easier to read, but is not populated by this version.

The iframe URL ends with `&f9hookapi=true`, following the existing `?f9verticalthreshold=300px` query parameter. It registers one Hook API implementation with `beforeDisposition`; do not register another alongside it. CAV synchronization failures are logged with `####` but do not block hook-controlled disposition. If Five9 forces a system completion that bypasses the hook, the extension cannot prevent that server-side action or update CAVs after cleanup; it logs `Five9 bypassed the disposition hook` and saves the note only. Live development testing must establish which automatic completion paths invoke the hook; do not treat the fallback as successful CAV synchronization.

Notes use Navusoft's existing `Portal.model.note.Note` model and `POST /rest/note/new`. Only the master Five9 instance requests a save. Duplicate events are suppressed, with attempted/saved call IDs and saved note/account IDs kept in session storage across page refreshes. A repeated hook may retry the CAV update without creating another note. Changing Related To after the note is saved is rejected rather than relabeling the note with a different account. Failed or unacknowledged writes are not retried automatically: check the account's notes before manually retrying to avoid duplicates. Note contents and credentials are not stored in extension storage.

Filter the browser console by `####` and enable **Preserve log** before reproducing a refresh/disposition issue. `#### Five9 Related To selection retrieved` shows the selected object's `id`, `name`, and parsed Navusoft `accountId` (null when invalid). Step-by-step note-save diagnostics are omitted to reduce console noise. The selection log contains account data; redact it before sharing.

Temporary diagnostics also log the final disposition payload with credential fields redacted. That existing payload log contains call/customer data; avoid sharing it unredacted. No transcription lookup is performed.

Search uses `GET /rest/contact/search` with `searchKey=C`, `searchType=2`, `searchSite=false`, and `searchContact=true`. A page-context bridge uses Navusoft's existing session at request time; credentials are not copied into extension storage, messages, or logs. Keep the Navusoft portal signed in. The official stable Five9 CRM SDK is bundled for use inside the ADT iframe.

Full top-level page navigation destroys all page-owned elements. When this occurs, the dock starts minimized and the Five9 iframe must initialize again. A replayed call event can reopen the dock. Keeping one uninterrupted Five9 runtime across full page navigation requires a separate browser window.

## Test this version

1. Open `chrome://extensions` and enable **Developer mode**.
2. Select **Load unpacked** and choose this `EMBEDDED` folder.
3. Open or reload https://bigssanitation.navusoft.net/.
4. Select the circular **F9** button in the bottom-left corner to open the square Five9 panel. Use the header's minimize button or Escape to collapse it back to the circle.
5. With no active call, open the dock, then reload or navigate to another full Navusoft page. Confirm it starts minimized even though it was previously open.
6. Sign in to Five9, minimize the dock, and receive an inbound call. Confirm the adapter becomes visible before answering, including when contact lookup fails or finds no match. Confirm a single Contacts match opens its record in Navusoft without reloading the Five9 iframe. Manually type a number into Five9 and dial it; confirm the same lookup runs using the dialed number. Start a call from a Navusoft click-to-dial link and confirm no lookup runs. Confirm other outbound call types do not trigger a lookup.
7. Test a caller number with multiple Contacts matches. Confirm Navusoft opens its Contacts search grid with that number and allows selecting a record.
8. Click a phone number in a grid or account detail. Confirm Five9 opens with that number and uses its normal dialing flow. Check a dynamically loaded record and an existing telephone link as well.
9. During a call, open two different accounts and confirm both appear in Five9's Related To list. Select the first, open the second again, then disposition the call. Confirm exactly one Service Note appears on the selected first account, not the currently displayed second account. Repeat with a browser refresh before disposition, without revisiting the selected account: confirm the retained Related To selection saves the note without a missing-account warning and final comments update that same note. Confirm clearing Related To still shows the confirmation.
10. Reload the extension and portal so the iframe has the Hook API flag. In a development environment, configure `Navusoft.account_id` and `Navusoft.note_id`, then confirm `Navusoft note and account call variables saved; allowing disposition` appears before the disposition payload. Confirm missing CAVs, failed writes, and failed readbacks log an error but allow disposition without a blocking dialog or duplicate note. Verify final subject/comments update the existing note. Repeat with ACW expiry to determine whether Five9 routes that automatic completion through the hook. Do not deploy to production until the required completion paths have been validated.

The manual Contacts search for `7249725640` returned one match; `3213617934` returned two matches during validation. An actual inbound Five9 call is still required to validate the complete live event flow.

Run the account-visit and call-note regression tests with `node --test NavuSoft/EMBEDDED/tests/accountLogging.test.cjs` from the repository root. Tests mock Five9 and Navusoft writes. The live note serialization check intercepted the request before sending, so no customer note was created during development validation.

The iframe uses the US Five9 URL, `https://app.five9.com/clients/integrations/adt.main.html`. Chrome may require third-party cookies and microphone permission for the embedded page.

The manifest runs only on HTTPS pages at `bigssanitation.navusoft.net`. Add another exact hostname to `manifest.json` if another Navusoft environment is needed.
